- **根因（5-Whys）**:
  1. 为什么上限是 10000？—— 复制自早期需求"全量导出"场景的宽松值，未按列表页重新裁剪。
  2. 为什么未统一？—— 不同开发者各写各的 `@Range`，无共享常量/统一策略。

  5. 为什么一直存在？—— 无静态扫描规则（如 ArchUnit/自定义 lint）约束 `@Range` 上限。
- **建议修复**: 引入统一常量（如 `ApiLimits.MAX_PAGE_SIZE = 100`），全局替换 `max = 10000`；管理端导出类接口单独走导出端点（异步/流式），不与列表分页混用。

### P1-I-2. PageResult 返回类型不一致 ⚠️ **已确认**（2 处核心 + 20 个 controller 混用）

**(a) `CourseController.getCourseStudents` → 全量 List 无分页**
- 位置: `controller/CourseController.java:219-221`
- 描述: `GET /api/courses/{id}/students` 返回 `R<List<EnrollmentVO>>` 全量学生列表，而 `EnrollmentService` 已存在分页方法 `getCourseEnrollmentPage(courseId, page, size)`（`EnrollmentServiceImpl.java:179`）未被使用。
- 影响: 大课（数百~上千人）时该接口一次返回全部学生，前端无法分页，且与相邻的 `GET /api/enrollments/course/{id}`（PageResult）行为不一致。

**(b) `DiscussionCommentController.page` 方法名与返回类型矛盾**
- 位置: `controller/DiscussionCommentController.java:26-28`
- 描述: 方法名为 `page` 但返回 `R<List<DiscussionCommentVO>>` 全量评论，无分页参数。讨论帖评论可能成百上千条。
- 影响: API 语义误导客户端；评论列表无分页上限。

**(c) 共 20 个 Controller 同时存在 `R<List<T>>` 与 `R<PageResult<T>>` 端点**
- 涉及: TeacherController / UserController / StudentController / CourseController / OrderController / MicroSpecialtyController / TeachingClassController / TagController / DepartmentController / ClassController / OfflineSessionController / EnrollmentController / MyReviewController / VideoController / ExerciseController / BadgeController / CourseExerciseController / CourseFavoriteController / CourseOfflineSessionController / MajorController
- 部分为合理（统计/树/常量类接口），但 `CourseController`、`EnrollmentController` 的若干 List 端点属业务数据列表，应统一分页。
- **根因**: 无统一的 API 契约（分页 vs 全量）评审机制；各端点按"当时够用"实现。
- **建议修复**: 对可增长的数据集合端点强制 `PageResult<T>`；导出类走 `XxxExportController`；新增 spec 约束"列表端点必须分页"。

## 五、扫描方法论说明

1. **@Range 上限**: 全量 grep `@Range(min = 1, max = \d+)` 于全部 Controller。
2. **PageResult 不一致**: 交叉对比 `R<List<T>>`（81 处）与 `R<PageResult<T>>`（50 处）在同一 Controller 的分布。
3. **@Valid 缺失**: Python 脚本解析全部 `@RequestBody`（141 个参数），按"@Valid 在 @RequestBody 前/后"双向检测 + 2 行回溯，人工复核 10 个候选，剔除 `String rawBody`（无需 @Valid）。
4. **ServiceImpl 超长**: `wc -l` 全量排序，>600 行 20 个。
5. **零引用**: 类名全局出现次数 == 1（仅自身声明），再经 Grep 工具复核排除误报（发现并排除 `TtsWorkerService` 自触发、`EnrollmentConverter`/`HtmlSanitizer` 方法名误报）。
6. **重复代码**: 手动 setter 计数 + 超长方法定位（>150 行 14 个）+ 具体代码块比对。
7. **异常过宽**: Python 提取每个 `catch (Exception e)` 块体，按"空/仅 log/有业务语句"分类。
