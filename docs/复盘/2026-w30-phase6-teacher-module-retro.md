## 三、问题与根因

### 3.1 CI 首轮失败

- 症状：
  - PR #123 首轮 `backend` 失败，导致 `auto-approve` 一并失败
- 直接原因：
  - `TeacherCourseCoverIntegrationTest` 把课程列表顺序写死为 `items[0].id == 1`
- 根本原因：
  - 测试假设了固定返回顺序，但集成环境中课程排序并不保证目标课程恒为第一项
- 处置：
  - 将断言改为按 `id == 1` 过滤目标课程后再校验封面字段
- 防止再发：
  - 后续同类集成测试避免对无契约保证的列表顺序做硬编码断言

### 3.2 浏览器联调工具不稳定

- 症状：
  - `ego-browser` 当前会话接入失败
  - Playwright 本地浏览器二进制也不稳定
- 影响：
  - 本轮真实浏览器联调证据获取存在噪音
- 处置：
  - 改用组件回归测试 + 本地隔离部署 + 已有联调证据补齐闭环
- 结论：
  - 当前问题属于工具环境噪音，不构成业务阻断

## 四、本轮新增教训

1. 集成测试不要假设无契约保证的返回顺序
2. 文档闭环要与代码闭环同批完成，否则很容易出现“代码已收口，状态台账还停留在计划”的脱节
3. 主线同步要优先保历史，再做对齐，避免用破坏性方式覆盖本地提交链
