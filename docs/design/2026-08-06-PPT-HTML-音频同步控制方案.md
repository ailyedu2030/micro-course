## 1. 背景与目标

### 1.1 用户诉求

> "课件讲述稿生成系统和 TTS 使用 MMX（MiniMax）…… 现在还不能跟着 PPT 或 HTML 控制播放。"

拆解为三个可验收目标：

| 目标 | 含义 | 验收 |
|------|------|------|
| T1 PPT 驱动播放 | PPT 每页一段音频；翻页/自动播放与音频严格联动；音频播完自动进入下一页；支持页间跳转逻辑（flow） | 教师/学生在 PPT 课件中：音频与页面同步切换、播完自动翻页、flow 规则（NEXT/BRANCH/SKIP）生效 |
| T2 HTML 驱动播放 | HTML 单个课件内多段音频；音频时间线与 DOM 段落映射；播放时当前段高亮；点击段落可跳转到对应音频 | HTML 课件中：音频播放时对应段落高亮、点击段落跳转播放、进度条可拖动、播完自动进入下一互动 |
| T3 MMX 链路闭环 | 讲述稿生成（AI）与 TTS（MiniMax）在 v1/v2 两条链路都真实可用、参数一致 | v2 工作台"AI 生成"真实返回并保存；v2"生成音频"真实调用 MiniMax 并完成；音色/模型参数前后端一致 |

### 1.2 设计原则

1. **UX 至上（L0 宪法）**：播放器交互符合直觉——点哪段播哪段、当前段高亮、进度可拖、自动播放可开关。
2. **回归 Hermes 原设计**：`docs/postMessage-音频控制方案.md` 的父页宿主思路是对的（iframe 不持有音频，统一由平台播放器控制），本方案在协议 v1 基础上平滑升级为 v2，**不再**在 iframe 内注入/播放音频。
3. **向后兼容**：协议 v1 消息（`slide-audio` / `slide-audio-state`）保留解析；旧课件（legacy `slide_pages`）与 V2 新表（`slide_ppt_pages` / `slide_html_units`）双轨读取；灰度开关不破坏现有功能。
4. **渐进实施**：P0 先打通播放链路与修复存量缺陷 → P1 PPT flow 驱动 → P2 HTML 分段高亮 → P3 AI 真实化与增强。

## 3. 关键决策（含备选方案对比）

### 决策 1：音频宿主——父页单音频 vs iframe 内多音频

**选定：父页单音频宿主（AudioHost）**，即回归 `docs/postMessage-音频控制方案.md` 的 Hermes 原设计。

| 维度 | 父页单音频（选定） | iframe 内多音频（现状 D1 路径） |
|------|------------------|-------------------------------|
| 进度条/倍速/拖动 | 单一控件，天然统一 | iframe 内各自播放，父页需聚合 |
| 自动翻页 | ended 事件单点触发 | 需 iframe 回传，协议脆弱 |
| 安全 | iframe 无音频权限，全凭 postMessage 指挥 | 需在 sanitize 后的 HTML 注入脚本（已坏） |
| 播放失败/降级 | 父页可兜底提示 | iframe 内难以展示平台错误 |
| 兼容协议 v1 | 保留 `slide-audio-state` 推送，无缝 | 需重写注入脚本 |

结论：废除 `buildSegmentControllerJs()` 注入方案（含 D1 修复），HTML 课件不再内嵌 `<audio>`/控制器脚本；HTML 仅保留"内容渲染 + marker 元素 + postMessage 指挥"，音频统一由平台 AudioHost 播放。

### 决策 2：播放协议——v1 扩展 vs v2 重写

**选定：协议 v2（player.js 风格），向后兼容 v1**。

- 理由：v1 只有 play/pause/seek/speed/get-state，缺少"段级控制"（segmentIndex）、"段元数据下发"（segments 清单）、"高亮通知"（segment-activated）、"握手/就绪"（ready）与"受限提示"（blocked）——这些是 T2（HTML 控制播放）的必需能力。
- 兼容：SlidePlayer 同时监听 v1 与 v2 消息；v2 消息带 `version: 2` 标识；旧 HTML 课件（仍发 v1）按 v1 处理。

### 决策 3：flow 求值位置

**选定（2026-08-06 第二轮定稿）：后端服务端求值（新增 `POST /courseware/{sectionId}/flow/evaluate`），播放器只传上下文；前端不做规则求值**。

- `NEXT`：线性默认（无规则时 page+1；有规则时后端返回 toPageId）。
- `BRANCH_DEPENDS`：依赖 quiz 结果 → 后端 `FlowEngine` 复用现有 `BranchFlowHandler`，在服务端读取测验完成状态（播放器不需要也不应有权限读取他人 quiz 数据）。
- `SKIP_IF_KNOWN`：后端 `SkipIfKnownFlowHandler` 已实现白名单安全求值（`user_progress >= 0.8` 等字段比较），不引入任意 JS eval。
- 理由：后端 `FlowEngine` + `FlowHandler` 链已存在且实现安全求值（`micro-course-api/.../plugin/interactive/flow/`）；BRANCH 依赖的 quiz 上下文在服务端可达，前端直接读存在权限/时效复杂度；规则变更即时生效（每次翻页请求 evaluate，无缓存回放问题）。
- 兼容兜底：evaluate 接口异常/超时 → 播放器退化为线性 page+1，保证播放不中断。

### 决策 4：getPages 数据源

**选定：v1+v2 聚合（服务端），优先 v2**。

- 顺序：section 下存在 `slide_ppt_pages` → 返回 PPT v2 节点（含 activeScript/activeAudio/flow）；存在 `slide_html_units` → 返回 HTML v2 节点（含 segments + 每段 activeAudio）；两者皆无 → 回退 legacy `slide_pages`。
- 播放器无需感知 v1/v2，统一消费 `SlidePageVO` 扩展字段。

### 决策 5：MMX 音色/模型契约

**选定：后端为唯一真相，前端下拉与后端常量对齐**。

- 后端暴露 `GET /api/courses/{cid}/courseware/tts-options`（或静态常量下发）：`models: [speech-2.8-hd, speech-01, speech-02]`，`voices: [{label:'女声·少女', id:'female-shaonv'}, ...]`。
- 前端 `AudioManager`/`ScriptEditor` 改用该接口渲染选项；删除 `MiniMax-speech-01/02`、`male-young/female-young` 等与 MiniMax 不符的枚举。
- 遗留旧数据（voice 存了 male-young 等）：生成时做别名映射（male-young→male-qingnian 等）或直接回退默认音色。

## 5. 数据契约扩展（播放器消费层）

### 5.1 `SlidePageVO` 新增字段（服务端聚合填充）

```jsonc
{
  "pageNumber": 1,
  "contentType": "PPT_RENDERED | HTML_DIRECT",
  "narrationStatus": "AUDIO_READY | PENDING | AUDIO_GENERATING",
  // PPT 模式（v1 或 v2 均归一化到该结构）
  "audio": { "url": "/api/courses/1/courseware/audio/<token>", "durationMs": 125000, "scriptId": 3 },
  // HTML 模式（单页多段）
  "segments": [
    { "index": 1, "marker": "seg-1", "selector": "#seg-1", "text": "本节要点…",
      "audio": { "url": ".../<token>", "durationMs": 30000, "scriptId": 8 } }
  ],
  // PPT flow（全 section 级，放在每页节点或顶层均可，播放器按 fromPageId 建索引）
  "flows": [
    { "fromPageId": 1, "toPageId": 2, "flowType": "NEXT", "priority": 0,
      "dependsOnQuizId": null, "conditionExpression": null }
  ]
}
```

### 5.2 HTML marker 注入约定

- 后端聚合时对 `html_sanitized` 做**只读增强**（不落库，读时组装）：
  - 为每个 segment 找到其 DOM 锚点（`segment_marker` 若为 id → `#id`；否则按顺序取首个 `h1/h2/h3/section/p` 元素边界）并注入 `data-segment="N"`；
  - 注入平台 CSS：`[data-segment].active { outline: 2px solid #6366f1; background: rgba(99,102,241,.08); transition: all .25s; }`；
  - 注入轻量 `bridge.js`（非音频控制器）：监听 `click` 的 `[data-segment]` → `parent.postMessage({type:'slide-audio-v2', action:'segment-active', index})`；上报 `ready`；接收 `segment-activated` 高亮消息。
- sanitize 白名单同步放行 `data-segment` 属性与 `style`（仅平台注入）。

## 6. 播放协议 v2 规范（player.js 风格）

所有消息 JSON 对象，首字段 `type`；HTML→父为 `slide-audio-v2`，父→HTML 为 `slide-audio-state-v2`；均带 `version: 2`。

### 6.1 HTML → 父（指令）

| action | payload | 说明 |
|--------|---------|------|
| `ready` | `{segments:[{index, marker}], interactive: true}` | iframe 加载完成握手；父页回 `loaded`（含段元数据与音频 URL） |
| `play` | `{index?}` | 播放指定段（缺省=当前段/第一段） |
| `pause` | `{}` | 暂停 |
| `seek` | `{index, time?}` | 跳转到段起点或段内 time（秒） |
| `set-speed` | `{rate}` | 倍速 |
| `segment-active` | `{index}` | 用户点击了某段 → 父页 seek 到该段播放 |
| `get-state` | `{}` | 查询状态 |

### 6.2 父 → HTML（事件）

| state | payload | 说明 |
|-------|---------|------|
| `loaded` | `{segments:[{index,url,durationMs}], totalDurationMs}` | 音频元数据就绪 |
| `playing` | `{index, time, duration}` | 开始播放某段 |
| `paused` | `{index, time, duration}` | 暂停 |
| `time-update` | `{index, time, duration, progress}` | 时间刷新（HTML 内部用于高亮边界/自绘进度） |
| `segment-activated` | `{index}` | 通知 iframe 高亮对应 `[data-segment]` |
| `ended` | `{index, nextIndex}` | 段播完；nextIndex=null 表示整个课件结束 |
| `blocked` | `{reason:'autoplay'}` | 浏览器拦截自动播放，需用户点击 |
| `error` | `{code, message}` | 音频加载/播放失败 |

### 6.3 安全校验（父页接收侧）

> **P0 修订（2026-08-06 论证发现）**：srcdoc + sandbox（无 allow-same-origin）iframe 的 origin 为 opaque，`MessageEvent.origin` 返回的是**字符串 `"null"`** 而非 JS `null`；`event.origin !== null` 恒为 true，会把 iframe 全部消息拒之门外（D9）。正确写法：

```js
if (event.origin !== 'null') return         // P0 修复：srcdoc sandbox iframe 的 opaque origin 序列化为字符串 "null"
if (!msg || typeof msg !== 'object') return
if (msg.type !== 'slide-audio' && msg.type !== 'slide-audio-v2') return
// v1 白名单: play/pause/seek/speed/get-state/get-segments/container-control
// v2 白名单: ready/play/pause/seek/set-speed/segment-active/get-state
```

同时父→iframe 发送保持 `postMessage(msg, '*')`（opaque origin 下 targetOrigin 无法精确匹配，`'*'` 是唯一可行且安全的写法；消息内容不含敏感数据，且 iframe 无同源权限）。

### 6.4 与 v1 的兼容桥

- 父页保留 v1 处理分支（`slide-audio`/`slide-audio-state`），旧 HTML 课件继续工作。
- 父页向 iframe 推送时**双发**（v1 + v2）直到 iframe 首次 `ready`（v2 握手成功）后只发 v2；未握手 iframe 不推送 v2 消息。

## 8. HTML 驱动播放设计（T2）

### 8.1 播放器侧（父页）

1. 进入 HTML 页：从聚合 VO 取 `segments[]`（index/marker/audio），**预加载全部段音频 URL 元数据**（AudioHost 按段队列）。
2. 播放：`playSegment(index)` → 加载/播放该段音频；`timeupdate` 计算 `activeIndex`（按段累计 startMs/endMs 或播放器自身维护当前段）→ postMessage `segment-activated` + `time-update`。
3. 段播完：`ended` → `nextIndex` 存在 → 自动续播下一段（段间 0.5s 停顿，交互页停留等待）；全部播完 → 课件结束/进入下一节。
4. 点击跳转：iframe `segment-active` → `seek` 到该段起点播放（若是互动段则仅激活不高亮播放，交互后由 iframe 请求播放）。
5. 进度条：显示段边界刻度（P2 可选）。

### 8.2 iframe 侧（内容桥）

1. 平台注入 `bridge.js`（非音频控制器，纯事件转发）：
   - `DOMContentLoaded` → `parent.postMessage({type:'slide-audio-v2', action:'ready', segments:[...]})`；
   - 委托点击 `[data-segment]` → `segment-active`；
   - 接收 `segment-activated` → 切换 `.active` 类；接收 `time-update` → 段内进度条（可选）。
2. 移除对 `AUDIO_SEG_XX_URL` 占位符的依赖（v1 legacy 课件继续兼容：仍可替换占位符 + 旧 v1 控制器，但新上传课件不再注入音频脚本）。
3. 互动段（`data-interactive="true"`）：播放完该段后不自动续播，显示"完成"按钮（复用现有 interactive-mask），点击后继续下一段。

## 9. Autoplay 解锁设计（D8）

浏览器硬约束（MDN/Chromium）：无用户交互前，未静音音频自动播放被拒。

1. `useAutoplayPolicy.js`：
   - 启动时 `navigator.getAutoplayPolicy?.()`（或 `media.play().catch(e => e.name === 'NotAllowedError')` 探测）。
   - 首次 `pointerdown/keydown` 在父页捕获（`{once:true}`）→ 执行一次静默 `audio.play()` 建立激活链 → `unlocked=true`。
   - 若 `policy === 'user-activation-required'`：进入页面**不自动播放**，显示"▶ 点击开始"（现状已有 ready 按钮，统一文案与触发）。
2. iframe 内点击不构成父页用户激活 → HTML 内点击播放请求在未解锁时父页回 `{state:'blocked', reason:'autoplay'}`，iframe 显示提示"请先点击页面下方播放按钮"；父页自身播放按钮/舞台点击作为解锁点。
3. 播放器顶部自动播放开关（autoMode）保留：未解锁时自动模式推迟到首次点击后生效。
